# ABX 盲听测试

一个纯本地的音频 ABX 双盲对比 Web 应用。上传 A、B 两段同格式音频后，服务端生成随机 X 题序（提交前映射完全隐藏），你在 A / B / X 之间自由切换试听并逐题作答，提交后一次性揭晓正确率与逐题映射。

- 后端：Node.js + Express
- 前端：浏览器 Web Audio API（无框架、无构建步骤）
- 数据：音频与会话**仅保存在本机**，不经过任何外部服务

## 功能特性

- 上传 A、B 两个**同格式**音频（WAV / MP3 / FLAC / OGG / M4A / AAC / OPUS / WebM / AIFF）
- 统一时间轴：自动以较短音频的时长为准
- 服务端用加密随机数生成每题 X = A 或 B 的映射，提交前任何接口都不泄露
- X 音频以 chunked 流式下发（无 Content-Length / 文件名），避免按文件大小猜测
- 试听页在 A / B / X 间切换时**保持播放位置与暂停状态**，可拖动进度条
- **片段循环（A–B 循环）**：在统一时间轴上一键设置入点 / 出点（区间至少 0.5 秒，不足时自动调整），播放到出点即采样级精确跳回入点；切换 A / B / X、换题或拖动进度后循环区间与播放 / 暂停状态保持，且循环点不会越过较短音频的有效时长；进度条下方高亮显示循环范围与启用状态，可一键清除
- **可选电平匹配**：解码后在统一时间轴内汇总各声道样本计算 RMS，以较安静音源为基准仅衰减较响者（-24～0 dB），A / B / X 经 GainNode 按同一规则生效；界面显示 A/B 调整量（dB），开关关闭立即恢复原始电平，消除响度差造成的盲测线索
- **可配置的等功率交叉淡化**：A / B / X 切换时新旧音源从同一时间位置并行播放，按 sin/cos 等功率曲线完成增益交接，时长 5～100 ms 可调（默认 30 ms），可整体关闭；快速连续切换时从当前听感增益重新锚定并取消过时节点与回调，不叠加、不爆音、不漂移；循环区间与电平匹配在淡化期间同时生效
- 逐题作答，可随时返回任意题目修改答案；全部作答后才能提交
- **可恢复会话**：创建测试后生成本机恢复标识，刷新或重新打开页面可找回未提交的会话（当前题号、已选答案、题目音频）
- 提交后一次性揭示：总正确率 + 逐题「X 实际是 / 你的答案 / 对错」
- 提交或删除后恢复标识立即失效；会话默认 24 小时过期自动清理，也可手动删除

## 快速开始

### 方式一：Docker（推荐，单条命令）

```bash
docker compose up --build
```

启动后访问：**http://localhost:3000**（端口 `3000`）

更换宿主机端口：

```bash
PORT=8080 docker compose up --build
```

停止并清理数据卷：`docker compose down -v`

> **会话恢复与容器**：恢复标识保存在浏览器 localStorage 中，音频保存在命名卷 `abx-data` 里，因此容器重启（`docker compose restart` / 重新 `up`）后刷新页面无法找回会话——会话状态（含 X 映射）只存在于服务进程内存中，重启即失效，这是有意设计。卷中的音频文件会随过期清理机制删除；`docker compose down -v` 会连同卷一起删除。

### 方式二：本地 Node.js（单条命令）

```bash
npm install && npm start
```

启动后访问：**http://localhost:3000**（端口 `3000`，可用 `PORT` 环境变量覆盖）

要求 Node.js ≥ 18。

## 使用流程

1. 打开首页，选择音频 A 和音频 B（需同格式），设置题目数量（1–50，默认 8）
2. 点击「开始测试」，浏览器解码音频并进入试听页
3. 每题中点击 **A / B / X** 切换音源对比试听，切换时播放位置与暂停状态保持不变；可开启「切换淡化」并设置时长（5–100 ms，默认 30 ms）让新旧音源等功率平滑交接，不需要时可在界面关闭；可开启「电平匹配」消除 A/B 响度差造成的盲测线索；可用「⇤ 设为入点 / 设为出点 ⇥」循环试听某一片段（见下）
4. 对每题选择「X = A」或「X = B」，可通过「上一题 / 下一题」或进度圆点返回修改
5. 全部作答后点击「提交并揭晓答案」，一次性查看正确率与逐题映射

**片段循环（A–B 循环）**：播放或暂停时点击「⇤ 设为入点」「设为出点 ⇥」，即可把当前播放位置设为循环起点 / 终点（先后次序不限）。出点设定后播放立即从入点继续，形成无缝循环；循环区间最短 **0.5 秒**，若设定的区间不足会自动调整入 / 出点满足下限。进度条下方的高亮条实时显示循环范围与入 / 出点刻度，状态行显示「循环已启用 / 未设置」；「清除循环」一键取消。切换 A / B / X、切换题目或拖动进度都不会清除循环区间，也不会改变播放 / 暂停状态（拖动到出点之后时，本次会播放到时间轴末尾，回到区间内后循环继续生效）；循环点始终限制在较短音频的有效时长内。

**中断与恢复**：测试进行中刷新或重新打开页面，首页会出现「继续上次测试」卡片，点击即可回到上次题号继续作答（已选答案与题目音频一并找回）；也可以选「放弃并删除该会话」。提交、删除或会话过期后，恢复标识立即失效，卡片不再出现。

## 实现原理

- **统一时间轴**：前端用 `decodeAudioData` 解码 A、B 后取 `min(durationA, durationB)` 作为播放上限，所有音源共用该时间轴
- **进度保持**：播放引擎记录「起始偏移 + AudioContext 起始时刻」，切换音源时在原偏移处重建 `AudioBufferSourceNode` 继续播放；暂停状态下切换只换缓冲
- **片段循环**：入 / 出点基于统一时间轴（秒），启用时使用 `AudioBufferSourceNode` 原生 `loop` + `loopStart` / `loopEnd`，到达出点采样级精确跳回入点；显示位置按「入点 + (经过时长 − 入点) mod 区间」回绕。设置 / 清除循环点时以当前位置无缝重建播放（保持播放 / 暂停状态），设定出点时若当前位置已越过出点则立即跳回入点；循环点被钳制在统一时间轴（较短音频时长）内，区间不足 0.5 秒时自动调整
- **电平匹配**：可选。解码后在统一时间轴内汇总全部声道样本计算 RMS，以较安静音源为基准仅衰减较响音源（限制在 -24～0 dB；RMS < 1e-6 或非有限值时保持 0 dB）。A、B 与每题 X 各经一个 `GainNode` 按同一规则应用增益，切换音源 / 拖动进度 / 换题不中断播放，关闭开关立即恢复原始电平
- **等功率交叉淡化**：可选，时长 5～100 ms。每个发声实例为 `AudioBufferSourceNode → 淡化 GainNode → 电平匹配 GainNode`；切换音源时全部旧实例按 cos 曲线从各自当前听感增益（读取音频渲染线程的实时值）淡出并定时回收，新实例从同一时间位置按 sin 曲线淡入，交接中总功率保持恒定；快速连续点击会取消过时的增益事件与回收定时器并重新锚定，始终平滑转向最后一次选择；暂停、拖动、换题、循环变更立即收束全部实例与回调，保持原有状态语义
- **映射隐藏**：X 映射只存在于服务端内存；`/trial/:n/x` 接口以 `application/octet-stream` + chunked 传输下发音频，不暴露文件大小与文件名
- **可恢复会话**：创建会话时服务端生成高熵随机恢复标识（recovery token），明文仅随创建响应下发一次，由浏览器保存在本机 localStorage；服务端只存其 SHA-256 哈希。恢复接口 `/api/session/recover` 凭标识只返回非敏感状态（题数、已选答案），绝不提前返回 X 映射；当前题号由浏览器本地记录。提交、删除或过期清理时标识立即从内存移除
- **本地存储**：音频写入本机 `./data/<sessionId>/`（Docker 中为命名卷 `abx-data`），会话状态仅存内存，默认 24 小时过期清理

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/session` | 上传 A/B（multipart 字段 `a`、`b`、`numTrials`），创建会话与随机题序，返回恢复标识 `recoveryToken` |
| POST | `/api/session/recover` | 凭 `{token}` 找回未提交会话的非敏感状态（题数、已选答案；不含 X 映射） |
| GET | `/api/session/:id` | 会话状态（题数、已答情况；不含 X 映射） |
| GET | `/api/session/:id/audio/A`（或 `B`） | 下载参考音频 |
| GET | `/api/session/:id/trial/:n/x` | 下载第 n 题的 X（按隐藏映射返回 A 或 B 的内容） |
| POST | `/api/session/:id/answer` | 保存/修改某题答案 `{trial, answer}` |
| POST | `/api/session/:id/submit` | 提交，一次性返回正确率与逐题映射（幂等）；恢复标识同时失效 |
| DELETE | `/api/session/:id` | 删除会话及其音频文件；恢复标识同时失效 |

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口 |
| `DATA_DIR` | `./data`（容器内 `/app/data`） | 音频文件保存目录 |
| `SESSION_TTL_MS` | `86400000`（24h） | 会话过期时间（毫秒） |

## 说明与限制

- 音频格式支持取决于浏览器的解码能力（`decodeAudioData`）
- 会话保存在内存中，服务重启后进行中的会话会失效（恢复标识一并失效；音频文件会随过期清理机制删除）
- 恢复标识只保存在本机浏览器 localStorage，换浏览器/换设备无法恢复；清理浏览器站点数据会使其丢失
- 本工具面向本机自测场景；刻意抓包比对字节流理论上可推断 X，正常使用界面则完全盲测
